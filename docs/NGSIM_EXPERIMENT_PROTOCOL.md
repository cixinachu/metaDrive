# NGSIM 主线实验协议 v1

本协议把完整官方轨迹表转换为可审计的实验片段。完整下载、质量筛查、场景分类和实验抽样是四个不同步骤；下载行数不是车辆数，也不是独立场景数。实际统计以 `datasets/experiments/ngsim-mainline-v1/summary.json` 为准，不能用原始行数宣称实验规模。

## 数据来源与完整性

来源是美国交通部发布的 [NGSIM 官方轨迹表](https://data.transportation.gov/resource/8ect-6jqj.json)，[官方目录说明](https://catalog.data.gov/dataset/next-generation-simulation-ngsim-vehicle-trajectories-and-supporting-data)。下载器对四个地点按 Socrata 行 ID 排序分页，逐页检查行数并保存 SHA256，支持断点续传，最终合并为 `datasets/raw/ngsim/full/trajectories.csv`。总表包含 I-80、US-101、Lankershim 和 Peachtree；“完整”指该官方表的所有轨迹记录，不包括原始视频、GIS 和其他附件。

`manifest.json` 记录来源 URL、查询行数、下载时间和总文件 SHA256；`pages/*.json` 记录每页来源及校验值。官方表本身含重复记录，不能把它们当新增车辆。历史元数据和 data.gov 对许可版本的展示存在差异，应保留来源声明并按实际数据许可使用。

本环境只支持高速主线，因此只筛选 I-80 和 US-101。城市道路数据保存在原始总表中，不强行转换为直道。匝道相关行也保留在原始表中，但主线实验不回放非主线车道。

不存在所有论文通用的 NGSIM 筛选标准。下面除注明借鉴的跟驰持续时间外，均是本项目 v1 的工程与实验选择。原始轨迹筛查也不等于论文使用的重构轨迹，未进行隐式平滑或宣称获得地面真值。

## 固定划分：先分记录，再选片段

采集记录以 `(location, global_time - frame_id × 100ms)` 标识，避免不同采集记录重复使用车辆 ID。配置保存准确的六个记录起点。

| 实验划分 | 数据 | 用途 |
| --- | --- | --- |
| train | I-80 最早采集记录 | 更新四个算法的参数 |
| validation | I-80 后两个记录，与训练记录相隔约一小时 | 选择超参数、检查训练和确定 checkpoint |
| test_ood | US-101 全部三个记录 | 配置冻结后进行跨地点、六车道到五车道测试 |

不随机拆帧，不随机拆同一辆车的重叠窗口。训练和验证在时间上隔离，测试在地点上隔离。相邻记录间可能存在重叠交通，但本协议把有重叠的记录放在同一划分内。

**test_ood 是跨地点测试，不是 IID 测试。** 只有两个高速地点，不能因此宣称覆盖了道路总体分布或完整的同分布泛化能力。验证集不可代替最终测试集，测试结果不可反复用于调参。

## 质量筛查与候选窗口

规则机器可读版本：`configs/datasets/ngsim_selection_v1.json`。

1. 全表原始文件 SHA256 必须与下载清单匹配。先删除完全重复的原始行，再对使用的轨迹字段去重。同一记录、同车、同时间的冲突状态会使该车辆整条轨迹不参与候选和回放，记录数量。
2. 自车为 `v_Class=2` 乘用车。I-80 主线车道 1–6，US-101 主线车道 1–5。自车长 2–8m、宽 1–3m。背景车允许其他车辆类别。
3. 自车窗口固定 20 秒，必须包含 201 个连续 0.1 秒状态。缺帧、驶出主线或尺寸不合法会断开连续段，不跨断点拼接自车。背景车缺帧则拆段，缺失期间不生成车辆。
4. 每个记录中的每辆合格自车最多一个候选窗口：存在稳定相邻换道时，优先围绕最早换道取窗，边缘不足则移动窗口；否则取最长连续有效段的中间 20 秒。该规则本身偏向包含换道事件，不能把候选集称为自然交通的随机抽样。
5. 自车由位置差分得到的纵向速度在 −2～55m/s，横向速度绝对值不超过 8m/s；非有限数据拒绝。允许少量测量抖动，不用加速度/jerk 或 TTC 阈值删除危险驾驶。
6. 对所有候选检查窗口内背景轨迹明显跳变：相邻 0.1 秒的纵向位置差分超出上述范围，或横向差分超过 8m/s，则拒绝窗口。正式生成回放时再核验保留段的差分速度。不通过的窗口有拒绝原因；这是保守质量门槛，应报告其对数据分布的影响。
7. 自车矩形宽度必须处于重建主线范围内；窗口开始时不能与背景车辆轴对齐矩形重叠。不是删掉未来危险，只是避免初始化即相交。初始矩形检查是直道近似，不等同完整的旋转多边形碰撞证明。
8. 道路宽度固定 3.6576m/车道，重建长度不能超过 900m。位置不平滑，英尺换米，车头中心减半车长得到车中心。背景速度由位置差分生成；源数据的速度只用于记录轨迹 TTC 标签。

自车不要求最低平均车速或最低位移，因此拥堵/停车仍可能出现。停滞片段的“到达原轨迹末端”指标可能不适用，应同时查看路线进度、碰撞、风险和速度，不能只看成功率。

## 四类片段：互斥标签和优先级

优先级为自车换道 → 邻车切入 → 持续跟驰 → 其他主线。

- **ego_lane_change**：自车车道 ID 变化为相邻主线车道，变化前后分别至少 10 帧保持稳定；短暂的单帧标签抖动不算换道。
- **cut_in**：自车保持同车道，记录的前车 ID 发生改变；新前车一秒前处于相邻主线车道，随后至少一秒保持自车车道；切入后纵向净距在 0～60m。这里是基于记录的切入标签，不保证 RL 改变自车轨迹后仍发生同样关系。
- **car_following**：同一前车与自车在同车道、前车在前方的连续时间 **超过 15 秒**。其余时候可有前车变化，片段总长仍为 20 秒。
- **other_mainline**：通过质量检查但不满足上述事件的主线行驶，包括弱交互或部分拥堵情况。

另计算记录轨迹的最小正 TTC：有效同车道前车净距除以正的闭合速度（闭合速度须大于 0.1m/s）。`TTC<3s` 仅用作风险标签，未达到条件或无可观测 TTC 分开解释；绝不把“无 TTC”理解为安全。没有用 RL 模型效果筛选场景。

## 实验抽样与公平比较

全部候选与拒绝原因保存在 `candidates.csv`。每个划分、每类最多选 30 个，按固定 seed=20260924 和候选 ID 的 SHA256 排序截取，结果保存在 `selected.json`；不满足上限时保留实际数量。该上限控制首次正式实验的规模，不代表仅下载这些数据。改变上限或其他规则应另建协议版本、重新生成并冻结实验集。

扩充版 `ngsim-mainline-v2` 使用独立配置、随机种子和审计清单，由 `scripts/select_ngsim_v2.py --config configs/datasets/ngsim_selection_v2.json` 生成；它排除了 v1 已选中的同一地点、采集记录、自车和起始时刻窗口，每类每划分最多增加 70 条。v2 的固定成员列表是单独版本，不能与 v1 混合重复计数；页面为方便浏览合并展示两版。当前总量为 1,058 条，v2 的详细摘要位于 `datasets/experiments/ngsim-mainline-v2/summary.json`。

四个算法必须使用同一 `selected.json`、相同观测/动作、奖励、cost、控制频率、终止条件和训练步数。建议至少 5 个训练种子，逐模型在同一验证/测试列表评估；不能用不同算法各自筛选“容易”的片段。

批量训练在选中的 train 片段中均匀有放回抽样。批量评估对指定划分每个选中片段恰好运行一次，不将同一确定性片段换 seed 当作独立样本。

结果至少报告：每类的成功率、碰撞率、越界率、累计 cost、平均速度、路线进度，以及折扣 cost 的 CVaR 和有效尾部样本数。抽样是按类别分层的，直接平均反映这个分层实验集；不代表自然交通事故概率。可以用各类合格候选数量做加权均值，但仍只代表本协议候选分布，不能把加权均值代替加权分布计算 CVaR。

同一记录内不同自车会共享周围交通，片段并非相互独立。置信区间应至少按时间块/采集记录聚类，并结合训练种子报告离散程度；本协议记录数少，不应给出过度精确的总体安全结论。

## 使用方式

```bash
# 完整下载，可重复运行续传；不是下载两个演示窗口
python scripts/download_ngsim_full.py
# 从完整表生成统计、候选索引和正式回放片段
python scripts/select_ngsim.py

# 批量训练；另外三个名称：sac_lagrangian、wcsac、wcsac_iqn
python scripts/run_ngsim_experiment.py train --algorithm sac --seed 0 --timesteps 100000
# 先验证并确定模型，再进行冻结后的跨地点测试
python scripts/run_ngsim_experiment.py eval --algorithm sac --model models/实际任务/model.zip --split validation
python scripts/run_ngsim_experiment.py eval --algorithm sac --model models/实际任务/model.zip --split test_ood
```

批量入口的模型写入 `models/`，评估写入 `results/`；保存实验成员清单、片段指纹、逐回合 CSV、JSONL、TensorBoard 事件与汇总。批量入口采用无画面的训练/评估。网页可逐片段选择、预览、训练和评估，仍使用原有的画面、曲线与下载功能；不要把网页的单片段训练当作整个数据集训练。

## 环境含义和边界

这是轨迹驱动的在线仿真 RL：自车从实测状态初始化后由算法控制，背景车按真实轨迹回放。它不是直接使用离线数据更新策略的“离线 RL”。背景车不会因自车动作避让，碰撞也不改变其后续轨迹；道路是等宽直线近似，并非恢复全部实测几何。它能比较固定交通轨迹下的策略表现，不能单独证明真实闭环交通安全性。

本次验收：`outputs/ngsim_full_acceptance.json`（350 个片段及 12 组回放）、`outputs/ngsim_algorithm_acceptance.json`（四算法多片段更新/保存/加载）、`outputs/ngsim_cli_acceptance.json`（批量命令端到端）、`outputs/ngsim_ui_acceptance.json`（网页筛选与真实预览）。这些是接口验收，正式算法性能对比尚未运行。
